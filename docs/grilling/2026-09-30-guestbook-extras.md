# /grill-with-docs 기록: 방명록 번외 기능

필수 CRUD 이후 추가할 네 가지 기능(글자 수 표시, 좋아요, 비밀번호 연속 실패 제한, 더 보기)의 설계 인터뷰 기록.
확정된 용어는 `GLOSSARY.md`, 되돌리기 어려운 결정은 `docs/adr/`에 반영했다.

## Round 1

❓ **Q1 - 좋아요 중복 방지**: 로그인이 없는데 좋아요 중복을 어떻게 막을까? (브라우저당 1회·취소 가능 / 무제한 / 브라우저당 1회·취소 불가)

➡️ 추천: 브라우저당 1회, 취소 가능

✅ 결정: **브라우저당 1회, 다시 누르면 취소** → ADR-0002

---

❓ **Q2 - 비밀번호 연속 실패 제한**: 기준은? (글마다 5회 실패 시 5분 / 3회 실패 시 10분 / IP 단위)

➡️ 추천: 글마다 5회 실패 시 5분 잠금

✅ 결정: **글마다 5회 실패 시 5초 잠금** (과제 시연용으로 짧게) → ADR-0001

---

❓ **Q3 - 더 보기**: 한 번에 몇 개씩, 어떤 방식으로? (10개 + 버튼 / 5개 + 버튼 / 무한 스크롤)

➡️ 추천: 10개씩 + "더 보기" 버튼

✅ 결정: **5개씩 + "더 보기" 버튼**

---

❓ **Q4 - 글자 수 표시**: 어디에? (작성·수정 둘 다, 한도 근접 시 색상 / 작성 폼만 / 이름·메시지 모두)

➡️ 추천: 작성·수정 메시지 둘 다, 900자부터 주황·1000자 빨강

✅ 결정: **작성 폼 메시지에만, 색상 변화 없이 단순하게** (`N / 1000`)

## Round 2 (Round 1에서 따라 나온 세부 결정, 기본값으로 확정)

- 잠금은 **글 단위**다. A 글의 실패는 B 글에 영향이 없다.
- 수정과 삭제는 **같은 비밀번호 시도**로 센다.
- 성공하면 연속 실패가 0으로 초기화된다.
- 5번째 실패에서 잠금이 걸리고 연속 실패는 0부터 다시 센다. 잠금 중인 시도는 비밀번호를 확인하지 않고 거부하며, 횟수에도 넣지 않는다.
- 잠금은 좋아요와 글 보기에는 영향이 없다.
- 틀렸을 때는 남은 시도 횟수를, 잠겼을 때는 남은 초를 안내한다.
- 더 보기는 URL(`?limit=`)로 상태를 표현한다. 새로고침이나 글 작성 후에도 보던 범위가 유지된다.
