# 잠금 상태는 서버 메모리가 아니라 DB의 글 행에 저장한다

앱은 Vercel 서버리스 함수로 돌아가서 요청마다 다른 인스턴스가 뜰 수 있고, 메모리에 둔 실패 횟수는 요청 사이에 사라진다. 그래서 연속 실패 횟수와 잠금 해제 시각을 각 글의 행에 컬럼으로 저장한다. 별도의 Redis 같은 저장소는 과제 규모에 비해 과해서 쓰지 않았다.

## Considered Options

- **서버 메모리(Map)**: 서버리스에서는 인스턴스가 바뀌면 초기화되어 제한이 사실상 동작하지 않는다.
- **IP 단위 제한 테이블**: 여러 글을 돌아가며 찍는 공격까지 막지만, 같은 네트워크의 방문자끼리 함께 막히고 IP 추출이 프록시 설정에 의존한다.
- **글 행의 컬럼 (선택)**: 추가 인프라 없이 글 단위 잠금을 정확히 표현한다.

## Consequences

- 잠금은 글 단위다. 서로 다른 글에 대한 시도는 서로의 실패 횟수에 영향을 주지 않는다.
- 동시에 여러 틀린 시도가 들어오면 횟수가 약간 덜 세어질 수 있다. 과제 수준에서는 허용한다.
