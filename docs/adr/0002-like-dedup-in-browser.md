# 좋아요 중복 방지는 브라우저 저장소로만 한다

로그인이 없어서 "누가 좋아요를 눌렀는지"를 서버가 신뢰할 수 있게 식별할 방법이 없다. 그래서 서버는 글마다 좋아요 수만 저장하고, 어떤 글에 좋아요를 눌렀는지는 방문자의 브라우저(localStorage)가 기억한다. 브라우저를 바꾸거나 저장소를 지우면 다시 누를 수 있는데, 이는 방명록의 가벼운 반응 기능에서 허용하는 한계다.

## Considered Options

- **무제한 클릭**: 가장 단순하지만 숫자가 의미를 잃는다.
- **IP 또는 쿠키 기반 서버 측 기록**: 좋아요 기록 테이블이 필요하고, 쿠키는 결국 브라우저 저장소와 같은 수준의 보장만 준다.
- **브라우저 저장소 + 서버 카운트 (선택)**: 스키마 변경이 컬럼 하나로 끝나고 체감 동작은 "한 번만, 취소 가능"과 같다.
